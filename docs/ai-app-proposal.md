# 生成AIアプリ企画案（あいちセレクトAIコンテスト提出用）

- **提出先**: [あいちセレクト AIコンテスト](https://aichi-select.net/ai_contest/)（ユメカタリ 学生生成AIコンテスト2026）
- **参加部門**: 開発部門（実装されたAIアプリ・ツール・サービス）
- **企画名**: Lipl（リプル）
- **キャッチコピー**: お店の情報を入力するだけ。3分で公式ページを公開。

> 企画段階だった提出（当初はクリエイティブ部門）から、実際にAIヒアリング〜LP自動生成〜即時公開までを実装したため、開発部門へ切り替えて更新。

## 1. 解決したい課題

個人経営の飲食店（カフェ・居酒屋・ラーメン店・キッチンカーなど）の多くは、公式ページを持たずSNS（Instagramなど）のみで営業案内をしている。理由は「難しいから」ではなく「手軽さ」の欠如にある。

- 制作会社への依頼は数日〜数週間、フォーム入力型のホームページ作成サービスでも項目を埋めるだけで半日仕事になる
- 「文章を書く」「レイアウトを選ぶ」「写真を配置する」――やることが多く、忙しい店主は結局後回しにする
- SNSだけでは営業時間・メニュー・電話予約導線などの基本情報が一枚のページにまとまっていない

## 2. 企画概要

Liplは、「書く」「選ぶ」「配置する」をぜんぶAIに任せ、店主がやることはチャットに一言ずつ答えるだけ、というサービス。店舗情報・写真・メニューを登録し、AIヒアリングの質問に答えると、生成AIが公式ページ（LP）のキャッチコピー・説明文・レイアウトを自動生成し、専門知識なしで即公開できる。

| | 一般的な制作方法 | Lipl |
|---|---|---|
| かかる時間 | 数日〜数週間 | 3分 |
| やること | 文章を書く／レイアウトを選ぶ／写真を配置する | チャットに一言ずつ答える |
| 必要な知識 | Web制作・デザインの基礎知識 | なし |

```text
店舗情報入力
  ↓
AIヒアリング（チャット形式・一言ずつ回答）
  ↓
公式ページ自動生成
  ↓
生成と同時に即時公開
```

## 3. ターゲットユーザー

- 個人経営の飲食店（カフェ・居酒屋・ラーメン店・レストラン・キッチンカー）
- Webサイト制作の知識・予算がない小規模事業者

## 4. 生成AIの活用ポイント（実装済み）

| 場面 | 生成AIの役割 |
|------|--------------|
| AIヒアリング | チャット形式で「お店のこだわり」「来てほしい客層」などをオープンクエスチョンで、一問ずつ引き出す（Claude Haiku） |
| LP自動生成 | ヒアリング結果と入力情報から、キャッチコピー・見出し・写真配置・電話予約ボタンまで含むページ全体のHTMLを自動生成（Claude Sonnet） |
| 生成と同時に公開 | 生成に成功した時点でそのまま店舗を公開状態にし、確認・公開の一手間を挟まない |
| 再生成・調整 | 生成結果を手動編集、またはAIに再生成させて上書き可能 |

用途に応じてモデルを使い分け（ヒアリング=Haiku・軽量、ページ生成=Sonnet・高品質）、Anthropicの静的APIキーは保持せず、KeycloakのOIDCトークンと交換するWorkload Identity Federationで都度短命トークンを発行して呼び出す。

## 5. 独自性・差別化ポイント

- **手軽さそのものが独自性** — 文章を書く・レイアウトを選ぶ・写真を配置するという作業を一切なくし、チャットに一言ずつ答えるだけで完結する設計
- **入力から公開まで3分**、しかも生成と同時に公開まで完了する一気通貫のフロー
- テンプレートへの当てはめではなく、AIヒアリングを通じて**店舗ごとの個性を言語化**してLPに反映する点
- AIが生成したHTMLをそのまま公開ページに使う設計のため、サーバー側でXSS対策のサニタイズを行いつつ、電話発信リンク等の必要な機能は失わないよう独自に調整している

## 6. 想定される効果・インパクト

- Web制作の知識・費用がなくても飲食店が自店の魅力を発信できるようになり、地域の個人店の販路拡大・売上向上に貢献
- 「手軽さ」のハードルを下げることで、これまで公式ページ作成を後回しにしていた店主の一歩目を後押しする
- 生成AIとの対話を通じて店主自身が「お店の強み」を再発見するきっかけになる

## 7. 今後の展望

- 多言語自動翻訳（メニュー・説明文の日・英・中・韓対応）によるインバウンド需要への対応
- QRコード発行機能（印刷して店頭に貼るだけで来店客をオンラインへ誘導する導線）
- アクセス解析・お知らせ投稿など、公開後の運用を支える機能の拡充

## 8. 技術構成

- フロントエンド: React Router v7 / TypeScript / Tailwind CSS
- バックエンド: Kotlin / Ktor / MariaDB
- 生成AI: Anthropic Claude（Haiku・Sonnet）、Workload Identity FederationによるAPIキーレスな呼び出し
- 認証: Keycloak（OIDC）、httpOnly Cookie + BFF方式によるログイン永続化
- インフラ: Kubernetes / ArgoCD（GitOps） / GitHub Actions
