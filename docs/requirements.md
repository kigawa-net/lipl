# Lipl Requirements

> 関連ドキュメント: [README.md](../README.md) | [CLAUDE.md](../CLAUDE.md)

## Vision

飲食店向けの公式ページ作成サービス。

キャッチコピー:

お店の情報を入力するだけ。3分で公式ページを公開。

## MVP Flow

```
会員登録
  ↓
店舗作成（店名・業種・所在地）
  ↓
フォーム入力（営業時間・電話番号・SNSリンク・写真・メニュー）
  ↓
AIヒアリング（チャット形式でお店の魅力・こだわりを引き出す）
  ↓
LP生成（AIがテキスト・レイアウトを自動生成）
  ↓
プレビュー（スマホ・PCで確認）
  ↓
公開（<slug>-lipl.kigawa.net で即時公開）
```

## 認証

- **Keycloak** を使用（`user.kigawa.net` で運用中のインスタンス）
- realm: `lipl`（新規作成）
- フロントエンドは OIDC (Authorization Code Flow + PKCE)
- バックエンドは JWT 検証（Keycloak の公開鍵で署名検証）
- パスワード管理・メール認証・パスワードリセットはすべて Keycloak に委譲

## ネットワーク

- **店舗LPデフォルトドメイン**: `<slug>-lipl.kigawa.net`
  - slug は店舗作成時にユーザーが設定（英数字・ハイフンのみ）
  - **グローバル一意**（全ユーザー間で重複不可。先着順）
  - ワイルドカード DNS `*.lipl.kigawa.net` で一括解決
  - Ingress は slug をホスト名によりルーティング
  - **slug 変更時のリダイレクト**: 全プラン共通で旧 URL から新 URL へ **1年間** 301 リダイレクト（Free を含む。QRコード等の印刷物が旧URLを指している場合の失効を防ぐため）
- **独自ドメイン** (Pro): ユーザーが DNS を `lipl.kigawa.net` に CNAME → Ingress で `customDomain` をルーティング
  - **所有権確認**: 別途の確認フローは設けず、設定された CNAME が Ingress まで到達し cert-manager の HTTP-01/DNS-01 チャレンジが成功したことをもって確認済みとみなす
  - チャレンジ未成功の間はダッシュボード上で「未検証」ステータスを表示し、独自ドメインでの公開は保留する
- **サービス自体**: `lipl.kigawa.net`（ダッシュボード・LP生成API等）

## AIヒアリングフロー

1. システムが店舗の基本情報（業種・所在地など）を読み込む
2. AIがオープンな質問をチャット形式で行う
   - 例: 「お店のこだわりを一言で表すと？」
   - 例: 「どんなお客様に来てほしいですか？」
   - 例: 「他のお店と違うと思うところは？」
3. 回答をもとにAIがLP用のキャッチコピー・説明文を生成
4. **質問数・生成回数の制限**

| プラン | AI質問回数 | LP生成回数 |
|--------|-----------|-----------|
| Free | 3回 | 1回 |
| Basic | 5回 | 月3回まで |
| Pro | 10回 | 月6回まで |

### 回数のリセット単位

- **AI質問回数**: LP生成・再生成を1回実行するたびに新しいAIヒアリングセッションが開始され、質問回数もそのセッション単位でリセットされる（セッションをまたいで積算しない）
- **AI生成回数（Free）**: アカウント（店舗）あたり生涯1回のみの買い切り。再生成したい場合はBasic以上へのアップグレードが必要
- **AI再生成回数（Basic/Pro）**: カレンダー月単位でリセット（毎月1日 0:00 にリセット）

| プラン | 枚数上限 | 解像度上限 |
|--------|----------|------------|
| Free | 15枚 | フルHD（1920×1080） |
| Basic | 40枚 | 4K（3840×2160） |

## お知らせ投稿仕様

- **対象**: Basic 以上
- **1件あたりの情報**: タイトル（最大50文字）・本文（最大1,000文字）・投稿日時
- **件数上限**: 上限なし
- **保持期間**: 削除するまで保持（自動削除なし）
- **公開 LP への表示**: 新しい順に最大5件を表示

## 多言語対応仕様

- **対象**: Pro プランのみ
- **翻訳方式**: Claude API（Sonnet）による自動翻訳
- **対応言語**: 日本語・英語・中国語（簡体字）・韓国語
- **翻訳対象**: LP のキャッチコピー・説明文・メニュー品名・説明文・お知らせ本文
- **翻訳タイミング**: LP 生成時または手動で「翻訳を更新」を実行したとき
- **URL構成**: 言語ごとに独立したパスを付与する（`/`=日本語（既定）、`/en`、`/zh`、`/ko`）。SEO設定（hreflangタグ等）と両立させるため、クライアント側トグルのみで同一URLを共有する方式は採らない
- **言語切替 UI**: 公開 LP 上部に言語切替ボタンを表示し、各言語パスへのリンクとして機能する

| 項目 | Basic | Pro |

## 運用ルール

### 複数店舗の運用（Basic・Pro）

| プラン | 店舗数上限 |
|--------|-----------|
| Free | 1 |
| Basic | 3 |
| Pro | 10 |

- 複数店舗を持つ場合、店舗一覧から1店舗を **メイン店舗** として指定できる（未指定時は作成日時が最も古い店舗をメイン店舗とみなす）
- メイン店舗の用途はダウングレード時の挙動（下記）で使用する

### 店舗・LP の削除

- 店舗削除または LP 非公開設定を行った場合、**即時**に公開 URL が非公開になる

### 決済失敗・サブスクリプション停止

- Stripe から決済失敗の Webhook を受信後、**3日間の猶予期間**を設ける
- 猶予期間中は現プランを継続。3日後に Free へ自動ダウングレード
- ダウングレード時、Free の制限を超えるデータは非表示になるが削除はしない
  - 複数店舗を運用していた場合、**メイン店舗のみ**公開を維持し、他の店舗は非公開になる（データは削除しない）
- 再決済が成功した場合は即時に元のプラン・元の公開状態（全店舗）へ復帰する
- **通知**: 以下の3タイミングでユーザーにメール通知を送信する
  1. 決済失敗を検知した時点
  2. 猶予期間終了の前日（ダウングレードのリマインド）
  3. ダウングレード実行時

### slug 変更

- 全プラン共通: 旧 URL から新 URL へ **1年間** 301 リダイレクト（Free を含む）
